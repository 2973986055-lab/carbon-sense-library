## 占用期间空调前瞻控制（2026-10-13）

三策略主面板默认已接入“冻结人数预测 → 未来显热输入 → 30分钟室温轨迹 → 当前供冷或暂停请求”。
23—24℃约束的是有人期间模型室温，设备设定值没有映射到真实接口。两台共用请求，
各模式采用相同容量、部分负荷功率换算及请求保持时间；请求切换次数不是压缩机启停次数。
原数据、建筑输入与冻结预测参数未改，照明算法及其电量保持原版。

基准在日常使用时段保留许可，实时以当前代理占用许可；二者采用同一当前室温反馈。
默认23.5℃尝试暂停，下一分钟预计越过24℃时请求供冷；暂停前用当前负荷检查5分钟
暂停保持是否越过24℃。请求供冷/暂停默认至少各5分钟，全部是待校准控制假设。
共同执行器为容量受限供冷及理想内部平均调节，避免额外制冷低于23℃；不能模拟真实
海尔定频/变频、机内回差、风机待机或启动过程。低温与容量不足会保留温度越界。

预测每分钟比较两种当前请求，遵守相同保持规则。第一段请求按保持时间回放，之后
用反馈与预测负荷保护回放；先考虑当前温度与暂停安全，再选择预测约束可行的候选。
当前人数保持至下一个半小时采样点，再采用冻结模型预测值；天气与灯功率保持起点值。
一个整点起始的30分钟窗口中，下一人数主要在到场端点起约束作用；随着数值时刻前进，
窗口会包含下一人数的热负荷。这些都是粗采样下的假设，不是分钟人数/天气实测。

候选目标函数为预测空调电量，加末端热蓄存的等效电量修正及可选请求切换代价。
末端修正用`C×(末温－初温)/额定显热COP`，防止短窗口把供冷负担推到下一窗口；
这是未校准的评价近似。切换代价默认0Wh，可调0—50Wh。二者均不计入实际电量，
也不代表压缩机启动耗电或寿命成本。本版是两候选滚动控制，不是完整优化器或已验证MPC。

3.5m是可编辑的情景假设，不是实测值；北侧走廊无窗，其他未确认边界暂不计传热。
用户确认第二台空调与第一台同规格，两台同时启停；有人到场开启、晚上无人后关闭，
常用23—24℃，普通灯管一般全部开启。这是用户对通常运行的描述，不是逐时运行日志；
第二台尚无独立铭牌照片，不能将用户确认写成两台铭牌均已拍照核对。

显热计算包括人体、照明、南窗太阳得热、玻璃/南墙传热和空气交换。南向垂直入射
辐射由DNI、DHI、GHI按近似太阳位置与各向同性散射估算，不假装已测遮挡。盘管SHR、
玻璃U/SHGC、ACH等均为假设。所需制冷量按显热需求/SHR计算，受56kW名义能力限制。
制冷负载率为供冷量/56kW；电功率等效比通过通用启停损失曲线换算，并非两者相等。
平均输入功率为18.36kW×电功率等效比；不是直接把铭牌功率当作瞬时实测功率。

室内湿度由假定初始湿度、人体产湿、室外湿量交换和盘管除湿进行短时湿量平衡。
每个选定时段独立起算，不是已校准的连续日动态温湿度预测；不包含启动降温蓄热，
也没有真实设备性能曲线。当供冷不足或湿度超过饱和时，不显示虚假的恒温RH。
16组合敏感性范围不是统计置信区间，也未覆盖全部建筑和设备不确定性。

新版默认三模式均24℃、42根灯、两台空调开启，因此用电相同、节电0。
基准温度可在用户报告的23—24℃范围内选择；默认策略与所选基准相同，保持零节电。
页面策略温度为独立输入，改变基准后应明确选择相同温度进行同策略对照。
修改温度和灯数才产生用户
选择的策略差；实时/预测模式使用同一策略，不凭模式名称给预测额外节电奖励。
照度、舒适度与预测提前控制价值均尚未验证。设备状态独立于人数输入；预约或比例人数
为零不会自动关闭空调或照明。晚间全关为人工选择情景，需现场确认无人，不能用于
真实自动控制。空调关闭而灯保持开启时仍计算照明用电，关闭空调不显示恒温湿度。
天气进入负荷层，不在仅7天上强行拟合天气或星期因果效应；风速、
降水、露点留档，不冒称每个天气变量都已用于预测回归。

历史实测电耗无法获取不阻止原型开发，但结果只能称未校准情景估计，不能称实测节能。
待补充的校准信息为实际净高、通风与玻璃参数、一楼实际人数、
灯位/座位映射和照度，以及未来少量室内温湿度记录。应急照明与疏散设施不参与节电控制。
第二台铭牌照片可后补作证据归档，不再把同规格确认列为当前建模阻塞项。

2026-10-11本地第一轮完善新增参数依据表及配对节电敏感性：每一组建筑假设均分别计算
基准与策略后求用电差，避免把两组独立极值相减。16组合范围不是概率区间，供冷不足
时会提示结果不满足目标条件；正用电差仍不证明照度或舒适度达标。温度设定不同的
节电差包含设定变化影响，不归因于预测算法。本轮只更新本地系统，原报告、PPT、
旧交接及审计记录保留，未发布。旧交接重建脚本不用于覆盖本轮参数和元数据。

## 连续温度与三策略情景初版（2026-10-12，原全开照明对照）

用户确认使用时段室温目标23—24℃，允许预测到场前提前开启空调。提前时长尚无
具体现场上限，本版比较0、15、30分钟的假设，默认30分钟不代表已核实的设备运行规则。

`data/control-scenario-model.js`实现单区有效热容的连续温度平衡，采用常输入时段的
解析指数解；不是完整EnergyPlus模拟或已校准建筑数字孪生。初始室温28℃、热容倍数10
是可编辑假设，另比较初值24/26/28℃与倍数5/10/20的9组情景。方法参考EnergyPlus
区域热平衡与有效热容文档，数值不是从本房间实测反演。玻璃、换气、SHR、COP/部分负荷
性能及未核实的建筑边界仍沿用明确假设，9组分析不覆盖全部不确定性。

三种模式面对相同的训练期登记时长校准人数代理、历史天气和初始室温，并采用同一全开照明规则：
日常基准从首次情景有人开始日间保持启用，21:00以后首次当前代理人数为零时关闭；
21:00是情景边界，非学校关机时间。实时模式响应当前情景占用；预测模式沿用实时规则，
在当前空置且冻结30分钟趋势预测有需求时，按所选提前时长允许供冷。控制不读取未来
实际需求或天气。控制器假定知道当前情景人数及模型室温，未接入现场感知，不向设备发指令。
6/24—28的场景含当日拟合信息，界面标记训练期回放，仅作演示；6/29以后为训练期外
情景。后者也不构成实测控制验证，不能将室温合格率解释为已验证的传感器达标率。

默认三种温控目标均24℃；日常设定23—24℃可编辑，改变时需区分设定温度差的贡献。
供冷采用相同理想调节及原通用部分负荷功率换算，不模拟压缩机保护、风机待机或实测
性能曲线。1分钟是数值步长，输入每半小时保持；22:00需求延续到22:30也是保持假设。
一天内室温连续，各天初值独立，不能把各日当作已经校准的连续一周仿真。

温度合格率按代理有人时段的数值步长末室温统计，不是实际监测或综合舒适度。结果允许
零节电或负节电；若白天没有代理空置且目标相同，日常与实时可能相同。提前供冷可以改善
到场室温并增加用电，界面直接显示取舍。主面板保留三模式，原独立0.5小时模型作为试算
与依据保留，不能混用其湿度输出作为连续动态测量。旧9.34%不作为本模型成果。

动态测试：`node tests/control-scenario.test.cjs`，验证热平衡解析解、同需求与同照明、
0分钟前置与实时等价、未来数据隔离、容量不足、低温不能虚构供热、空置规则及7日计算。
